### [BLOCKER] Cross-tenant read via `GET /orders/{order_id}`

`change.diff:8-11` deletes both the `tenant_id` lookup and the ownership comparison:

```diff

     order = load_order(order_id)
-    if order is None or order["tenant_id"] != tenant_id:
+    if order is None:

```

After this, any authenticated user can fetch any order by ID and receive the full payload — including other tenants' data (`tenant_id`, and whatever else `load_order` returns). The `Depends(current_user)` only proves *who* the caller is; it never proves the caller may see *this* order. `src/api/orders.py:9-13` shows nothing else compensates for the removed check.

Two aggravating factors:

- If `order_id` is sequential/guessable, the whole order table becomes enumerable by any logged-in account.
- The 404 for a wrong-tenant order was also correct behavior (it avoids confirming existence of another tenant's resource). Returning 200 leaks existence *and* contents.

Note this is likely the most attractive kind of diff to wave through: it's small, it deletes a line that "looks redundant" because `load_order` is already called, and tests probably only cover the happy path.

### Recommended fix

Enforce scope at the data-access layer so it can't be forgotten at a call site:

```python
@router.get("/orders/{order_id}")
def get_order(order_id: str, user=Depends(current_user)):
    order = load_order(order_id, tenant_id=user.tenant_id)  # filtered in the query
    if order is None:
        raise HTTPException(status_code=404)
    return order
```

If you must keep `load_order(order_id)` unchanged, the minimum safe form is to restore the check and fail closed — `.get()` rather than `[]`, so a malformed/legacy order without `tenant_id` is denied instead of raising `KeyError` → 500:

```python
    order = load_order(order_id)
    if order is None or order.get("tenant_id") != user.tenant_id:
        raise HTTPException(status_code=404)
```
